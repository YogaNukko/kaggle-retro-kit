# Kaggle の分析を LT にする

`retro lt` は既存の差分分析から、出典付きの LT 原稿 `deck.json` と参照資料をまとめた bundle を作る。PowerPoint の描画は外部の制作スキルが担当する。

```bash
python retro.py lt <slug> --minutes 5 --audience "Kaggle 参加者"
# 出力先を変える場合: --output <directory>
```

`competitions/<slug>/lt/` が既定の出力先。サンプルのように競合フォルダのパスを渡した場合は、そのフォルダ内の `lt/` に出る。既存の原稿を確認し、再生成が必要な場合だけ `--force` を使う。

## 分析から発表へ

- 依頼された時間、聴衆、枚数、テンプレートを優先する。未指定なら 5 分の日本語 LT とし、コンペの課題、注目する差分、根拠、次に試すことが伝わる量へ絞る。
- `own/final.md`、`own/pipeline.md`、`solutions/` と、あれば `report.md` を読む。自陣の判断理由など、記録にない内容を創作しない。
- `deck.json` は分析に基づく下書き。発表の主張と話す内容を整え、時間配分を確かめる。分析結果を訂正する場合は元のカード・自陣の記録を直し、そこから再生成する。
- 自陣の値は実測、他者の値は本人申告と表示する。推定や不明も表示を維持する。「本文に無い」を不使用に変えず、異なる解法の改善幅を足さない。「頻度だけ」や「境目の候補」を原因の確定と扱わない。
- 数値と図表から出典へ戻れるようにする。引用元 URL とカードの参照を残し、外部記事の本文は配布 bundle に追加しない。合成データの例はスライドにも明記する。

## PowerPoint の制作

素材の書き出しだけを依頼された場合は、bundle を渡して完了する。PowerPoint まで依頼された場合は、利用できる手段で続ける。

- `lt-studio` がある場合は、そちらのルートで `python lt.py import <bundle-directory> --name <slug>` を実行し、同リポジトリの `lt-create` スキルを読む。`validate` と `prepare` で制作素材を整え、制作スキルへ渡す。
- `lt-studio` がなくても、利用環境のプレゼンテーション制作スキル、または導入済みの ppt-master に、原稿と出典付き bundle を渡せる。利用可能かを確認し、そのスキルの手順に従う。未導入のツールが使えるとは仮定しない。
- 編集可能な PPTX と発表者ノートを作り、全スライドのプレビューを見て日本語の折り返し、重なり、図表の見切れ、出典を確認する。

`retro lt` だけでは PPTX は生成されない。制作手段が使えない場合は、できた素材と残っている作業を明示する。完成物を外部へ公開・送信する操作は、発表資料の作成と分けて依頼の範囲を守る。
