# 段 4 — 差分の分析

```bash
python retro.py diff <slug>      # → diff.md（階段・構成要素の行列・圏ごとの使用率・差分の順位）+ video/data.json
```

`diff.md` は生成物で手で直さない。文章は `report.md`（雛形あり）に書く:

1. **結論 3 行**: 上位に共通していたもの / 自陣に最も効いた差 / 次に持っていく 1 つ。`diff.md` の「差分の順位」と「段の階段」から取る。
   判定は道具が出したとおりに書く（*境目の候補* と *頻度だけ* を区別する）
2. **差はどの段にあるか**: 階段を読む。上の圏は単一モデルで勝ったのか合成で勝ったのか。中央値を使い「申告」と書く
3. **なぜ届かなかったか**: 差分の上位 3 つに 1 行ずつ。自陣の記録が読めれば日付・実験番号・当時見えていたこと・判断。
   ファイルに無い「当時の理由」は「理由は記録なし」と書き、作らない（ユーザーが後で埋める）
4. **教訓**: 4 区分、それぞれ根拠のカードか実験を添える

その後 `python retro.py lint <slug>`、`status.md` を更新、commit。報告: 結論 3 行 → 階段の読み → 差分の上位 3 → 判断待ち
（動画へ進む / 自陣のすぐ上の圏のカードを足す / 閉じる）。

約束: 別々の解法の申告を足さない。「頻度だけ」は因果ではない。採否を決めない。
